02A / DISK PREPARATION
↩ 返回本节课堂图解

新硬盘如何变成可以安装系统、保存文件的存储设备？

物理扇区 → 分区表 → 文件系统元数据

物理 / 逻辑结构区别

情境：你买来一块新 SSD，准备安装 Windows

原本“从按下电源开始”的案例默认机器已经安装好了系统。现在补充装机前提：一块能被控制器访问的存储设备，必须有可识别的分区组织和文件系统，系统文件与引导文件才能按对应布局被定位。以下划分借用传统机械磁盘的教材模型；现代 SSD 的闪存页/块、FTL 和逻辑扇区接口不是图中的机械扇区结构。

① 物理格式化（低级格式化）

传统教材定义：对磁盘的扇区进行物理组织，设置标识、数据和错误检测/纠正信息，使设备控制器能够识别并读写扇区。现代 HDD/SSD 的底层出厂组织通常由制造商完成；Windows 磁盘管理中的“格式化”一般并非重新执行这种低级格式化。

② 分区（Partitioning）

磁盘分区表说明各分区的范围和类型。GPT、MBR 首先是磁盘分区方案；FAT32、NTFS、ext4 则是文件系统类型。GPT 的元数据不等于某个分区，也不是所谓“GPT 文件系统”。一个磁盘可以有多个分区，不同分区可使用不同文件系统，也可能用于保留区域或特殊用途。

③ 逻辑格式化（高级格式化）

在分区或逻辑卷上创建特定文件系统的基本数据结构，例如卷信息、空闲空间管理信息、目录与文件元数据。对应教材中的 FAT、目录区、空闲链表示法，以及其他文件系统的超级块、inode、位示图等概念。并非所有文件系统都同时采用 FAT、inode 和同一种超级块布局。

操作回答的问题典型产物/管理对象
物理格式化设备怎样识别和可靠读写基本单位？扇区组织及底层校验机制（传统 HDD 模型）
分区整块盘划成哪几段，分别做什么？MBR 或 GPT 分区表与边界信息
逻辑格式化怎样在指定区域组织文件和目录？FAT32、NTFS、ext4 等文件系统的初始元数据

一块 1 TB 磁盘的具体教学实例

安装程序选用 UEFI/GPT 模式，在磁盘上建立 ESP、MSR、Windows 和恢复分区（这些是典型 Windows 部署布局，不代表必须有用户自建的 D 盘）。ESP 使用 FAT32 存放 EFI 启动文件，Windows 分区通常使用 NTFS；MSR 是保留分区，不等同于一块可直接存放用户文档的独立盘符。

易错区分：“分区”不等于“格式化”；“快速格式化”不等于物理低级格式化；安装系统之前准备磁盘，不等于每次电脑开机都重新分区或格式化。进行真实操作时，创建/删除分区或格式化可能造成数据损失，本页仅作机制教学。

原 PDF 支撑：第 67 页“磁盘布局：分区、卷与元数据”和第 73 页“格式化与挂载”；低级格式化细节是外部大学讲义扩展。参考：Texas A&M CPSC 410/611 Disk Management、Colorado State CS370 讲义，以及 Microsoft UEFI/GPT 文档。

02B / BOOT MODES
↩ 返回本节课堂图解

准备好磁盘后，每次按下电源究竟走哪条路？

装机准备和每日启动是两条时间尺度

时间轨道 / UEFI 与 BIOS 对照

① 安装或部署系统之前发生的事

设备底层已经可读写 → 初始化 MBR/GPT 分区方案 → 创建目标分区或卷 → 创建文件系统 → 将操作系统及引导文件安装到规定位置。这里的顺序是概念化依赖关系；实际部署工具可能交错或自动完成多个步骤。

② 日常开机（UEFI/GPT 常见方案）

CPU 执行固件代码，UEFI 完成初始化并按照启动项定位 ESP 中的 EFI 可执行程序（Windows 上通常是 Windows Boot Manager），再经启动管理器/加载器定位内核与必要的启动环境。内核建立自己的内存管理、驱动和调度等基础机制，随后启动用户态服务。ESP 是有文件系统的分区，UEFI 可以按其支持的文件系统访问引导文件。

③ 传统 BIOS/MBR 方案

BIOS 完成初始化后，从选定启动设备的引导位置读取并执行 MBR 引导代码；引导代码继续找到后续引导阶段，再装入操作系统。MBR 同时与传统分区表有关，但MBR 分区表本身不是完整操作系统引导程序。

④ 回到原案例：为什么浏览器还不能马上运行？

固件、引导程序、内核初始化完成后，用户会话环境和所需的系统服务才逐步建立。浏览器作为用户程序仍需要进程创建、地址空间、文件访问及设备服务；这些步骤在原案例后续章节继续讨论。

要比较的对象UEFI + GPT（典型）BIOS + MBR（典型）
引导程序入口ESP 中的 EFI 可执行文件MBR 的启动代码与后续阶段
分区组织GPT传统 MBR 分区表
启动时是否重新格式化否否
学习时应关注固件如何找到 EFI 启动文件固件如何进入 MBR 引导链
不要混同：BIOS 和 UEFI 是固件/引导接口类别，MBR 和 GPT 是分区方案；它们常成对出现，但并不是严格的同义词，也不能单凭看到 GPT 就推断所有机器的实际固件配置。

08 / ACTIVE RECALL

现在不看图，能否复述这个真实事件？

把五条关系同时放在脑中

① 位置：固件、引导映像、内核、内存、设备在哪里。② 权限：read 何时从用户态进入内核态。③ 时间：磁盘工作时，CPU 与阻塞线程如何变化。④ 资源：浏览器与音乐如何并发共享 CPU。⑤ 结构：不同内核设计与 VMM 如何组织这些机制。

1. 为什么已经有硬盘上的 OS，还必须经历固件和引导程序？

刚开机 CPU 从固件入口执行，内核与其运行环境尚未就绪。固件和引导程序将控制逐步交给内核，再由内核初始化系统。

2. 用户单击浏览器图标、浏览器执行库函数、浏览器发起系统调用：三者必定是同一件事吗？

不是。GUI 事件涉及用户界面程序处理；普通库函数未必进入内核；需要内核服务时才通过规定入口发起系统调用。

3. 系统调用已经切换到内核态，是否意味着 P 的 PCB 一定被换下？

不一定。权限级别转换与进程切换是两个不同维度，系统调用可能直接返回原进程。

4. P 因 read 阻塞，此时磁盘完成中断为什么可能打断 Q？

P 已阻塞，CPU 可以被调度给其他进程或线程 Q；设备完成是异步通知，当时占用 CPU 的可能是 Q。

5. 设备完成后，P 是否会直接从阻塞变成运行？

通常先解除等待条件变为就绪，随后经调度获得 CPU 才继续运行。

6. 单核音乐与浏览器交替推进是并行吗？实时系统只是执行得更快吗？

前者说明并发，不要求同时执行；实时重点是满足规定时限，而不是平均速度最快。

7. 微内核、分层、模块化、第二类 VMM 是四种可相互替换的操作系统类型吗？

不是。微/宏内核讨论特权服务布局；分层和模块化是组织方式；VMM 类型讨论虚拟化软件与硬件及宿主系统的关系。
