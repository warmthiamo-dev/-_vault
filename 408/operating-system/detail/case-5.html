设备控制器与编址：CPU 怎样与设备说话？

寄存器的职责与地址空间要分清。
情境与问题

打印机接到请求前，驱动首先要与设备控制器交互。设备的命令、状态、数据寄存器（或缓冲）并非同一回事；“端口”在这里可指寄存器的访问地址，而不一定是物理插座。

机制、推导与边界

独立编址将 I/O 端口与内存地址空间分开，通常使用专门 I/O 指令；MMIO 把设备寄存器映射到内存地址空间，以适当访存操作访问。访问权限、缓存属性和内存顺序仍受约束。

408 易错提醒：不把 MMIO 混为内存映射文件；不把状态轮询理解成每次访问控制器都必须忙等。

三种 I/O 控制方式：谁等待、谁搬数据？

轮询/中断的差异主要是等待；DMA 的核心是数据搬运主体改变。
情境与问题

假设打印或磁盘任务需要一批数据：轮询方式下 CPU 反复检查设备状态，数据搬运常由 CPU 指令完成；中断驱动允许 CPU 在设备准备期间执行其他工作，但数据传输仍可能需要 CPU 搬运。

机制、推导与边界

DMA 由 CPU/驱动设定地址、长度、方向，再由控制器直接在设备与主存间搬运数据，完成或出错时通知 CPU 收尾。DMA 可能与 CPU 争夺总线/内存带宽，且还需要关注 Cache 一致性。

408 易错提醒：DMA 不是“完全不需要 CPU”；中断方式也不等于“数据由设备直接搬到主存”。

I/O 软件层次：一次请求怎样下行、上返？

请求向下逐层细化，完成通知向上逐层汇报。
情境与问题

用户的 read/write 经系统调用进入内核。设备独立性软件负责统一命名、设备分配、缓冲等共性问题；驱动把上层请求变为控制器可理解的操作；控制器与设备执行传输。

机制、推导与边界

设备完成后通常由中断通知内核的相应处理代码，随后驱动和上层更新请求状态；若调用者在等待，则可能被唤醒并重新参与调度。write 返回、设备完成和持久化是三个不同的完成层次。

408 易错提醒：软件层次图中的箭头不意味着每经过一层就发生一次进程切换或真实磁盘访问。

SPOOLing：十份打印任务如何共用一台打印机？

输入：外部设备 → 内存暂存 → 磁盘输入井；打印：用户提交任务 → 磁盘输出井 → 输出暂存区 → 打印机。
先看打印主线

十位同学几乎同时提交打印作业。后台服务先把打印内容和相关作业信息保存到磁盘的输出井，按规则排队。输出服务依次取出，经过内存中的输出暂存区把数据送到打印机。用户进程完成“提交”后可以继续运行，但这不等于纸张已经打印完成；打印机仍然逐份处理。

再看完整 SPOOLing 结构

第二张图按物理位置横向分成三列：左侧是外部设备，中间是内存缓冲区，右侧是磁盘上的输入井和输出井。上方输入通道从左往右：输入设备 → 输入暂存区 → 输入井；下方输出通道从右往左：输出井 → 输出暂存区 → 输出设备。输入井是为了预先收集慢速输入设备的数据；输出井是为了先保存等待输出的作业。这两条路径是不同用途，不表示打印作业都必须经过输入井。

图中有意不为每个管理动作画一条线：后台的输入、输出服务和井管理负责安排数据转存、建立作业记录、排队与输出。它们是运行机制，不必和数据传递路径画成一堆交叉箭头。

408 易错点：磁盘上的“井”是持久的作业/数据暂存空间；内存缓冲区用于速度匹配；多个用户可以同时提交的是逻辑打印服务，物理独占设备不会因此同时打印多份；提交成功不等于打印成功。
资料定位：上传的《2027操作系统_看图复习(2).pdf》第五章，PDF 第 86 页；结构表达参考此前研究的大学操作系统教学资料对输入井、输出井与缓冲区的组织方式。本图为重新绘制的简化教学示意。

设备分配：设备、控制器、通道缺一不可？

按表核对物理连接资源及占用状态。
情境与问题

在教材的设备管理模型中，操作系统可以借助设备控制表 DCT、控制器控制表 COCT、通道控制表 CHCT 和系统设备表等结构维护关联关系。请求独占设备时先检查设备是否空闲。

单缓冲与双缓冲：为何三块数据耗时不同？

相同 T=10、M=2、C=6：单缓冲 42，双缓冲 38。
情境与问题

规定每块输入 T=10，系统缓冲复制到工作区 M=2，CPU 处理 C=6，连续输入三块，初始为空。单缓冲模型中，复制阶段会占用唯一缓冲区，不能与下一块输入重叠。第 1 块 T 0–10、M 10–12、C 12–18；第 2 块 T 12–22、M 22–24、C 24–30；第 3 块 T 24–34、M 34–36、C 36–42。

机制、推导与边界

双缓冲允许设备在填充另一块缓冲区时同时处理上一块：第 1 块输入 0–10、复制 10–12、处理 12–18；第 2 块输入 10–20、复制 20–22、处理 22–28；第 3 块输入 20–30、复制 30–32、处理 32–38。稳态每块时间：单缓冲常为 max(T,C)+M=12；双缓冲为 max(T,M+C)=10，但有限块总时间必须算启动与收尾。

408 易错提醒：不要把稳态时间直接乘 3；图中横向长度按同一时间比例绘制，块的执行位置应看清。
资料定位：上传的《2027操作系统_看图复习(2).pdf》第五章，PDF 第 81–82,93 页。

循环缓冲与缓冲池：缓冲区怎样周转？

循环缓冲关注读写指针；缓冲池关注缓冲块的队列流转。
情境与问题

循环缓冲使用多个槽位和读写指针组织连续数据流。若只根据读指针=写指针，可能无法区分空和满；可以采用计数、标志位或保留一个空槽的约定。图示使用 8 槽并保留一空槽，因此最大有效容量为 7。

机制、推导与边界

缓冲池将空闲缓冲、输入缓冲和输出缓冲组织到相关队列：设备输入→收容输入→提取输入→交付进程，进程输出→收容输出→提取输出→交付设备。缓冲块随业务变化，不永久固定属于输入或输出。

408 易错提醒：区分“工作缓冲区”与“缓冲队列”，也要区分容量 n 与可用 n−1 的两种环形队列模型。

机械磁盘几何与访问时间

寻道、旋转等待与传输不是同一个过程。
情境与问题

机械磁盘具有盘面、磁道、扇区和柱面等概念。同一柱面对应各盘面上半径相同的磁道。磁头定位目标磁道需要寻道时间；等待目标扇区旋转到磁头下方需要旋转等待；真正搬运扇区数据则需要传输时间。

机制、推导与边界

典型访问时间可概括为寻道 + 旋转等待 + 传输，实际请求还可能存在排队与控制器开销。假设每分钟转 7200 转，则一圈约 8.33 ms；在请求随机且旋转位置均匀假设下，平均旋转等待约 4.17 ms。

408 易错提醒：平均等待半圈需要随机到达等假设；不能把机械磁盘的几何寻道套用到 SSD。
资料定位：上传的《2027操作系统_看图复习(2).pdf》第五章，PDF 第 88 页。

磁盘调度：六种算法的磁头轨迹

相同请求、相同起点：按访问先后看轨迹，再按相邻点差值累加总移动量。C-LOOK 与 LOOK 本例恰好同为 120，但移动规则不同。
统一的计算条件

磁头从 50 出发，请求到达顺序为 10、90、55；磁道编号 0～199，初始向大磁道方向移动。每张小图纵向按时间展开，标在圆点旁的“0·50、1·55……”表示访问顺序，虚线用于强调循环算法在端点处的回绕。

逐算法求和

FCFS：50→10→90→55，40+80+35=155。SSTF：50→55→90→10，5+35+80=120。SCAN：50→55→90→199→10，5+35+109+189=338。C-SCAN：50→55→90→199→0→10，5+35+109+199+10=358（将回绕移动计入）。LOOK：50→55→90→10，5+35+80=120。C-LOOK：50→55→90⇢10，5+35+80=120（将最大请求到最小请求的回绕移动计入）。

特别注意：本题只有三个请求，所以 LOOK 和 C-LOOK 的总磁头移动量巧合地相同，但 LOOK 是到当前最大请求后反向服务较小请求，C-LOOK 则是单向服务，回绕到最小请求再继续同向。对于 C-SCAN、C-LOOK，题目若规定不计回绕移动，需要按题设另算；本图将所有物理磁头移动计入。

扇区交错编号：圆形盘面上的逻辑顺序

交错编号：逻辑相邻 ≠ 物理紧邻；通过扇区之间的距离，给早期控制器留出处理时间。
具体情境

图中每一块扇形表示同一磁道上的一个物理扇区位置。沿磁盘旋转方向观察，物理位置上的逻辑编号依次是 0、4、1、5、2、6、3、7，而应用按逻辑序列 0→1→2→3……访问。为从 0 读到 1，物理位置需要越过中间的一个扇区。

机制与边界

早期控制器处理完当前扇区后可能需要一定时间准备下一次传输。若逻辑相邻扇区在物理上紧挨，控制器可能错过下一个扇区而等待额外一周。交错排列让连续逻辑扇区之间留下处理时间。图中具体的 8 扇区排列是简化模型，不代表真实盘片的全部组织，也不意味着交错编号会改变盘片的转速。

408 易错点：磁盘每转一圈的时间没有改变；要不要采用交错编号由控制器速度和题目条件决定，现代设备并非一律采取这种传统方式。

SSD：逻辑地址不变，物理页为什么会换？

页级读写、块级擦除，FTL 维护逻辑到物理映射。
情境与问题

假设更新逻辑页 L7。SSD 通常将新版本写到其他可用物理页，FTL 修改 L7→新物理页的映射，旧页被标记为无效。更新逻辑地址不会直接意味着覆盖同一个物理闪存页。

机制、推导与边界

垃圾回收选定擦除块，先转移其中仍有效的数据页，然后按块擦除并回收空间。磨损均衡避免少数块承担过多擦除次数。写放大来自有效页搬移和其他内部写入，具体值依实现与负载变化。

408 易错提醒：机械硬盘磁头调度的 SCAN/SSTF 与 SSD 的 FTL/GC 是不同机制。

scanf("%c", &d)：一次输入怎样经过中断、唤醒和系统调用返回？

看懂两条线：时间线上先发生 read 阻塞 → 设备中断 → 满足读取条件 → 唤醒就绪 → 调度运行；数据线上先到控制器 → 内核输入缓冲 → 用户态标准库缓冲 → 变量 d。
最小代码与前提

char d; scanf("%c", &d);。以下假设标准输入来自终端、C 标准库没有预存字符、采用阻塞式 read() 与终端规范模式（行缓冲式输入）。scanf 是 C 标准库函数，并非系统调用；在这个具体场景中它会请求内核读取数据。若 stdin 已缓冲了字符，则可以直接返回而不必进入内核。

① 到 ②：为什么会阻塞？

程序运行到 scanf，用户态标准库发现没有可用输入，就通过 read 请求内核读终端。内核发现还没有满足条件的一行数据，令当前读线程睡眠，CPU 转去执行其他任务。此时 read 尚未返回，scanf 也尚未结束。

③ 输入 A：为什么仍然不能返回？

键盘或终端控制器在输入数据就绪等条件下引发设备中断，处理程序经驱动读取输入数据并送入内核终端输入缓冲。硬件中断不一定等到控制器缓冲区满。 在所假设的规范模式下，按下字符 A 后，终端输入缓冲已经有 A，但还没有一整行供阻塞的 read 返回，所以等待线程仍可能处于阻塞态。

④ Enter 后：阻塞 → 就绪，不等于直接运行

按下 Enter，换行进入内核终端输入缓冲，完整一行可读。内核唤醒等待在该输入条件上的线程，令其从阻塞态进入就绪态。此时线程只是具备运行条件，是否立刻获得 CPU 取决于调度器。

⑤ 获得 CPU：复制、返回、赋值

当线程再次被调度，它继续此前尚未完成的 read()，把所需数据从内核终端输入缓冲复制到标准库管理的用户态输入缓冲（典型 stdio 实现），随后系统调用返回用户态。scanf("%c", &d) 解析第一个字符 A，把它写入变量 d。多出来的换行符可能仍留在标准库缓冲中，影响后续输入操作。

用户理解的流程与实现边界

你提出的“键盘输入 → I/O 接口 → 中断 → 驱动 → 内核缓冲 → 唤醒 → 就绪 → CPU → 复制到用户缓冲 → 系统调用返回”作为阻塞式终端读取的主线是正确的。但“接口缓冲区满才触发中断”不是所有键盘的通则；在规范模式下，也应将“完整行就绪”作为唤醒阻塞读取者的关键条件。不同硬件与终端模式下，中断条件和可读取条件可能不同。

408 易错提醒：① scanf ≠ 系统调用；② 设备中断 ≠ 控制器缓冲满；③ 输入字符到达 ≠ read 已满足条件；④ 唤醒 ≠ 立即运行；⑤ 内核缓冲区 ≠ 标准库缓冲区 ≠ 局部变量 d。
